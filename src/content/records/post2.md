# Ydnil-poh Archive System

## Overview

This project is not a blog platform.

It is an experimental personal archive system designed around:
- semantic proximity
- slow accumulation
- AI-assisted memory organization
- spatial exploration instead of feed consumption

The archive is intended to function less like a publishing platform and more like a memory field.

Human-readable structure exists, but is intentionally minimized.

---

# Core Philosophy

## 1. The archive is not feed-oriented

This project rejects:
- infinite scrolling
- engagement ranking
- thumbnail competition
- aggressive content hierarchy
- productivity-driven timelines

Content is not organized to maximize clicks.

Instead:
- relationships
- density
- recurrence
- semantic gravity
are prioritized.

---

## 2. Uniformity is the default state

The interface should feel:
- quiet
- stable
- grid-oriented
- minimally expressive

Content units should appear visually equal at first glance.

Importance should emerge subtly through:
- density
- spacing
- semantic clustering
- motion
- field distortion
rather than explicit ranking.

---

## 3. AI reorganizes memory

The system intentionally allows mismatch between:
- human memory
and
- AI semantic interpretation

This mismatch is considered valuable.

The archive is not a factual database.
It is a continuously reinterpreted memory landscape.

Embeddings are used not as truth, but as an alternative reading of accumulated records.

---

## 4. Reorganization happens slowly

The archive does not update relationships in real time.

Semantic restructuring occurs during scheduled rebuild cycles
(usually daily/nightly).

This process is conceptually treated as:
- sleep
- dreaming
- memory consolidation

The archive "rests" and reorganizes itself.

---

# Interface Principles

## The interface should feel like:

- a quiet archive
- a storage wall
- a memory grid
- a semantic landscape
- a spatial notebook

## The interface should NOT feel like:

- a social feed
- a dashboard for productivity
- a recommendation engine
- a gamified system
- a content marketplace

---

# Content Structure

Content is primarily written in markdown.

Metadata should remain lightweight.

Preferred metadata:
- date
- category
- optional location
- optional score

Avoid heavy manual tagging.

AI-generated semantic relationships are preferred over manually curated taxonomies.

---

# Spatial Structure

The archive is grid-constrained.

Avoid:
- chaotic force-directed graph layouts
- excessive animation
- unstable positioning

Prefer:
- stable placement
- slow rearrangement
- local displacement
- subtle clustering

The user should gradually develop spatial memory of the archive.

---

# Scoring

Scores are NOT popularity metrics.

Scores represent:
- semantic density
- recurrence
- relational gravity
- archival weight
- revisit potential

Scores may affect:
- spacing
- cluster influence
- visibility
- motion behavior
- field distortion

Scores should not create explicit ranking hierarchies.

---

# Technical Direction

Preferred architecture:
- static-first
- precomputed layouts
- nightly rebuild pipeline
- embedding-based clustering
- minimal frontend computation

Avoid:
- real-time force simulation
- constantly shifting layouts
- interaction-heavy UI

The archive should feel calm and durable.

---

# Sleep Cycle

During rebuild periods, the archive may enter a "sleep state".

Possible activities:
- embedding recalculation
- semantic clustering
- score updates
- spatial recomposition

This state is part of the archive's identity,
not merely maintenance downtime.
